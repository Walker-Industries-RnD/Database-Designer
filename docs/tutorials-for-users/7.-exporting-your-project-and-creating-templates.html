7. Exporting Your Project and Creating Templates

The Build Project page checks your project, builds everything you need to run it (SQL, security rules, C# and an API), and makes templates you can reuse or share.

Checking your project

  1. Open Build Project from the desktop.
  2. Press Build Check.

Build Check lists errors (would break the SQL or the API), warnings (probably mistakes) and tips. Click any line to open the table it's about. Fix the errors, then press Build Check again until they're gone. The full list of what it checks is in 1. Building Your Projects.

Exporting the full project

  1. Press Export.
  2. Press Build Project.

Each build goes into a new numbered folder (GeneratedDB\v1, v2 and so on) inside your project folder, so nothing is overwritten:

File Contents
SQL.sql The tables, keys, references and indexes
RLS.sql Roles and row level security policies
Migration.sql Upgrades a database built from the previous build
Documentation.md Every table and column, with your descriptions
Classes.cs C# classes for your tables
Models.cs An Entity Framework DbContext
API\ A working ASP.NET Core API with Swagger

Press View Builds to open the folder. To try the build on your own computer, see 7. Testing With Local Database.

Creating table (row) templates

A table template packs some of your tables (with their columns, references and indexes) so you can add them to other projects.

  1. Press Export Specific Rows.
  2. Templates tab: pick the tables. Each one shows up on the right, where you can give it a description.
  3. Pack Information tab: a banner (optional), the template name and an overview.
  4. Author tab: your name, plus an optional picture, company, website, license and note.
  5. Finalize tab: check the preview and press Finalize.

The list on the Finalize tab tells you what's still missing and updates as you type. The name can't contain \ / : * ? " < > | because it becomes a folder name.

Templates are saved to DatabaseDesignerData\<your username>\Row Templates\<Template Name>\v1\. Building the same name again makes v2, v3 and so on, and the newest one is used.

To use one, press Use A Template when creating a table. The full guide is in 5. Templates.

Creating full project templates

A project template is a copy of a whole project that new projects can start from.

  1. Press Export Template.
  2. Pick the project.
  3. Fill in the same information as for table templates.
  4. Press Finalize.

It's saved to DatabaseDesignerData\<your username>\Project Templates\<Template Name>\ with the project's tables, RLS, API design, NodeWalker graphs, icon and wallpaper.

💜 Exports are readable!

Templates and exported projects aren't scrambled with your account key, so you can open them, see exactly what's inside, and send them to a friend who can actually use them. When you import something it gets encrypted for your account, so your working copy stays private.


Sharing a whole project

Your projects are saved encrypted with your account, so you can't just copy the folder to someone else. To share one:

  1. Open Projects and press Export (Portable) on the project's card.
  2. This writes DatabaseDesignerData\<your username>\Exports\<Project Name>.ddproject (and a folder with the same contents).
  3. Send the .ddproject file.

Your Local Database connection is never included.

Importing projects

  1. Put the .ddproject file (or an exported project folder) in DatabaseDesignerData\<your username>\Imports\.
  2. Open Projects and press Import Project.

Each one becomes a new project, encrypted for your account. Imported files are moved to Imports\Imported\, so pressing Import twice doesn't make copies. If you already have a project with that name, a number is added (My Project (2)), so nothing gets overwritten.

💜 Free backups!

A .ddproject file is a full backup of your project. Keep one somewhere safe, and if anything goes wrong, drop it back into Imports\ and press Import Project. Easy!


The starter templates

Every account starts with these, so you have working examples to learn from:

Table templates (press Use A Template when creating a table):

Template What it gives you
User Accounts A users table: unique username and email, hashed password, created_at
Blog Posts A posts table: title, body, published flag, timestamp
Inventory Items An items table: unique SKU, name, quantity, price, JsonB metadata

Project templates (press Edit Template when creating a project):

Template What it gives you
Secure Sign-In users and sessions, ready for login and token flows
Simple Chat users and messages (each message points at its sender)
Simple Marketplace users, items (listed by a seller) and orders (a buyer buys an item)
Simple Store users, products and orders, plus five API functions with their NodeWalker graphs, including Stripe payments. See 9. Guide - Building A Simple Store

They're normal templates: open them, change them, or use them as a reference for your own.

Tips

  • Run Build Check first. It catches broken references before they break your SQL.
  • Give templates clear names and overviews. They're what people see when picking one.
  • A banner and author picture make your template easy to spot in the list.
  • Templates are versioned for you (v1, v2...), so you can keep improving one without losing the old version.
