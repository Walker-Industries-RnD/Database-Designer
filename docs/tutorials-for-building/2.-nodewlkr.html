2. NODEWLKR

NODEWLKR (NodeWalker)

NodeWalker is the node editor that holds the logic behind your API functions and RLS policies. You place blocks, wire them together, and NodeWalker turns the graph into C#. When you build your project, that C# goes into the exported API, so the graph you draw is the code that runs.

You don't open NodeWalker on its own. Every function in the API Editor and every policy in the RLS Editor has an Open in NodeWalker button, and each one gets its own graph.

The basics

Blocks

Every block has:

  • a title that says what it does
  • inputs on the left (what it needs)
  • outputs on the right (what it gives back)
  • sometimes a Value you type in, like the text of a String Literal or the field name for a Where block

Click a block to open it in the Node Inspector on the right, where you can edit its value and see its inputs and outputs.

Data wires

Drag from an output to an input to connect them. A data wire says where a value comes from: "the Count input of this block is the output of that block".

  • Yellow dot: required input. The block won't compile without it.
  • Red dot: optional input. If you leave it empty, a default (0, empty text, false) is used.
  • Purple dot: a custom type, like one of your table classes.

To remove a wire, click it and press Delete, or right-click it and pick Delete Connection.

Flow wires (the white pins)

Blocks that do something (save to the database, set a variable, fail the request) have white pins: In on the left and Then on the right. A flow wire says which block runs next.

Data wires answer "where does this value come from?" and flow wires answer "what happens next?". You need both once your logic has steps that depend on a condition or happen in a loop.

Graphs without any flow wires still work. NodeWalker works out the order from the data wires, the same as older versions did.

Flow blocks

Block What it does
Start Where the function begins. Wire its Then to the first step
Branch Runs the blocks wired to True when the condition is true, and the ones wired to False otherwise. After runs once either side has finished
Sequence Runs Step 1, Step 2, Step 3 and Step 4 in order. Later steps can use values made by earlier ones
For Each Runs Loop Body once for every item in Items. Item and Index only exist inside the loop
Repeat Runs Loop Body Count times, with Index counting 0, 1, 2 and so on
Try Runs Try. If anything in it throws (Fail If included), runs Catch instead and gives you the Error message
Return Stops here and returns the outputs set so far
End Where the function ends
Set Output Sets a value the function returns
Event Input / Custom Input Inputs to the function (see Custom Input below)

A few rules:

  • A Then pin leads to one block. If you want several things to happen, use Sequence.
  • Several paths can lead into the same block. If both sides of a Branch lead to the same block, it runs after the if/else.
  • Flow pins only connect to flow pins, and data pins only to data pins.
  • Value blocks (math, comparisons, Where blocks, Get Variable) are worked out right where they are used. A Get Variable inside a loop reads the latest value every time round.
  • If a block reads a value that only exists on another path (for example the Item of a For Each, used after the loop), View Code shows a warning above the code.

Comparisons

Equals, Not Equals, Less Than, Greater Than, Less Or Equal and Greater Or Equal compare any two values:

  • Numbers are compared by value, so an int and a decimal compare fine (5 equals 5.0).
  • Text that holds a number is treated as that number, so "10" is greater than 9.
  • Dates are compared as dates.
  • Anything else is compared as text.
  • An empty (null) value is smaller than everything else and only equals another null.

Before 3.0, some of these threw errors like "Object must be of type Double" when the two sides had different types. That's fixed. Graphs made in older versions pick up the fix the next time you build.

Query blocks (Lambda Logic)

These replace the old freeform Lambda block. Instead of typing x => x.Price > 10 you build the condition from blocks:

  • Where: Equals, Not Equals, Greater, Less, Greater Or Equal, Less Or Equal, Contains, Starts With, Ends With, Like, Is Null, Is Not Null, Is True, Is False, Between and In. Each one takes a field name (the column) and, where it makes sense, a value.
  • Where: And, Where: Or and Where: Not combine conditions.
  • Select: Field picks the column to sort or read by.
  • DB: Query filters, sorts and pages in one block.
  • DB: Select Field reads one column from the matching rows, and DB: Delete Where deletes them.

Plug a Where block into the Predicate input of DB: Get Where, DB: Get First, DB: Count, DB: Query and the other database blocks.

List blocks (List Logic)

For lists you already have (rows you loaded earlier, or a list from the request body): List: Filter, List: First Where, List: Any Where, List: Count Where, List: Sort By, List: Map Field and List: Sum Field. They take the same Where blocks as the database ones.

Custom Input

A Custom Input adds a parameter to the generated function. Set its value to CUSTOMINPUT(long) to give it a type, or CUSTOMINPUT(long orderId) to give it a name as well. Named inputs become named request parameters in the exported API.

RLS blocks

DB: RLS Set User and DB: RLS Set Role tell the database who is making the request, so the policies from the RLS Editor apply. Use them at the start of any graph that reads or writes rows that belong to a user.

Running a graph

▶ Run runs the graph you're editing against your Local Database (see 7. Testing With Local Database). It uses the tables from your latest export.

  1. Set up a database in Local Database and build it from your export.
  2. In NodeWalker, press ▶ Run.
  3. Fill in the inputs. Each box starts with an example of what it expects.
  4. Press Run. You get the result as JSON, or the error and the name of the block that failed.

Changes to the database are rolled back afterwards unless you tick Keep database changes. That includes graphs that commit their own transaction. Run needs the .NET SDK installed.

Saving

Graphs are saved inside the project, in its Scripts folder, one file per API function or RLS policy. They're included in portable exports and project templates, so your logic travels with the project.

Troubleshooting

"Required input not connected"
Wire every yellow input, or give it a literal value.

The code has a warning about a value from another path
A block is using a value that only exists inside a loop or on one side of a Branch. Move the block onto that path, or store the value with Set Variable and read it back with Get Variable.

Cycle detected
Some data wires go round in a circle. Use a flow block (Repeat or For Each) for loops instead of wiring a block back into itself.

Run says it can't find the database or the SDK
Set up the connection in Local Database first, build the database from an export, and check that dotnet --version works in a terminal.
