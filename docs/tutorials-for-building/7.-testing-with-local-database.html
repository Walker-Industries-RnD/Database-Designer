7. Testing With Local Database

Local Database lets you try your project on a Postgres database on your own computer before you ship it. You can build the tables, fill them with sample rows, run queries, and start the exported API, all from one window.

You'll need:

  • PostgreSQL running on your computer
  • the .NET SDK (8 or newer) for Start API and NodeWalker's Run button

Installing Postgres and the .NET SDK will get its own tutorial. Until then, the official installers from postgresql.org and dot.net work fine with the default settings.

Open Local Database from the desktop while a project is open. The window works top to bottom.

1. Connection

The box starts with:

Host=localhost;Port=5432;Username=postgres;Password=;Database=dd_dev

Put in your own password (and change the database name if you like), then press Test & save. The connection is saved inside the project, encrypted like the rest of it, and the database is created if it doesn't exist yet.

The connection is never included when you export or share the project.

2. Set up the database

Both buttons use your latest Build Project export, so build first.

  • Create from scratch drops this project's schemas and runs SQL.sql and then RLS.sql. Use it the first time, or whenever you want a clean start.
  • Apply Migration.sql upgrades a database built from the previous export and keeps its data. See 8. Migrations.

3. Sample data

Pick how many rows per table you want and press Add sample data. The rows look like real data (names, emails, prices, dates) and follow your rules:

  • Parent tables are filled first, so foreign keys always point at real rows.
  • Unique columns stay unique.
  • Lengths, Not Null and CHECK (column IN (...)) lists are respected.

The rows are also saved as SampleData.sql in the export folder.

4. Preview a query

Type SQL in the query box and press Run (Ctrl+Enter). Results show in a grid (the first 200 rows).

INSERT, UPDATE and DELETE are rolled back afterwards, so you can experiment freely. Tick Keep changes if you want them to stay.

5. Start the API

Start API runs the exported API with dotnet run against this database at http://localhost:5180 and opens Swagger, where you can call every route from the browser. Open Swagger opens it again, and Stop shuts the API down.

The first start takes a little while because .NET has to download packages and compile.

Running a single graph

You don't have to start the whole API to test one function. In NodeWalker, ▶ Run runs just the graph you're editing against this database. See 2. NODEWLKR.

💜 Break it on purpose!

This database is yours to wreck, so go try the weird stuff. Order 0 items. Order more than there is in stock. Delete a user who has orders. If something goes through that shouldn't, it's way better to find out here than after you ship it, dummy.
