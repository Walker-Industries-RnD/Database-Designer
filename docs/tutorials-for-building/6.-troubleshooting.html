6. Troubleshooting

The login button can't be clicked

Your firewall is probably blocking the background security service. Allow Database Designer.exe and Assets/Pariah API/Pariah API.exe through it.

"Error 500" when logging in

Usually a wrong password. It can also mean Database Designer can't write to the folder it's installed in, or the background service didn't start. Restart the app and try again. If you've forgotten your password, use Forgot Password? / Change Password on the login screen with your recovery code.

Build Check shows errors

Click an error to open the table it's about. The most common ones:

  • No primary key: tick Is Primary on one column (usually id).
  • Foreign key type mismatch: the column and the column it points at must have the same type, for example both bigint.
  • Foreign key target isn't unique: a reference has to point at a primary key or a column marked Unique.
  • Reserved word: rename columns like order or user to order_id or user_name.

"Connection failed" in Local Database

  • Check that Postgres is running.
  • Check the host, port, username and password.
  • The user needs permission to create databases the first time, because Test & save creates the database if it doesn't exist.

Run or Start API does nothing

Both need the .NET SDK. Open a terminal and run dotnet --version. If that fails, install the SDK (8 or newer) and restart Database Designer.

RLS doesn't seem to do anything

  • Superusers (like postgres) and roles with BYPASSRLS skip every policy. Connect your API with a normal role that is a member of the generated roles.
  • Check that RLS is on: SELECT relrowsecurity FROM pg_class WHERE relname = 'tablename';
  • Make sure your graphs use DB: RLS Set User and DB: RLS Set Role before reading or writing.
  • Check the line under each policy in the RLS Editor. If it warns about a missing owner column, only admins can see those rows.

The API returns 404

Routes are built from the module, endpoint and function names, lower-cased with dashes: api/<module>/<endpoint>/<function>. Open /swagger to see the exact routes, and check that you used the right HTTP verb.

The API returns "Not implemented yet"

That function has no NodeWalker graph yet. Open it in the API Editor, press Open in NodeWalker, build the logic, save, and build the project again.

Migration.sql didn't drop a table or column

Anything that deletes data is written but commented out, because a rename looks the same as a drop plus an add. Read it, uncomment the lines you mean, and run it.

A template doesn't show up

Make sure its folder is in DatabaseDesignerData\<your username>\Row Templates\ or Project Templates\, not inside a project. Templates from versions before 3.0 may need exporting again.

Colors look wrong or text is hard to read

Open Themes and press Set Default on Default. If one window is hard to read, use the transparency slider at its top right.
